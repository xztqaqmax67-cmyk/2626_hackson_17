# 17 队多核计算图调度程序

版本：0.8.4。工程使用 C++17 实现场景 B 的计算图切分与多核调度。输入计算图和核心数，输出操作到子图的映射及各核心的执行顺序，以降低 Makespan 和额外数据搬运量。

## 构建与运行

### Linux

环境：GCC 9.4 及以上、CMake 3.16 及以上。

在工程根目录执行：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
./build/bin/npu_sched "data/graph.json" -n 4 -o "out/plan.json"
```

### Windows

环境：Visual Studio 2019 16.8 或 Visual Studio 2022，CMake 3.20 及以上。

在工程根目录执行：

```powershell
cmake -S . -B build -A x64
cmake --build build --config Release -j
.\build\bin\npu_sched.exe "data\graph.json" -n 4 -o "out\plan.json"
```

构建产物统一位于 `build/bin/`。输入、输出路径支持相对路径、绝对路径、空格和中文；相对路径以程序启动目录为基准。输出目录不存在时自动创建。

## 命令行与数据格式

```text
npu_sched <graph.json> [-n N] [-o plan.json]
npu_sched --version
```

| 参数 | 说明 |
|---|---|
| `<graph.json>` | UTF-8 计算图 JSON，包含 `tensors`、`ops`、`edges` |
| `-n`、`--cores` | 核心数，支持 2、3、4、5，默认 4 |
| `-o`、`--output` | 输出路径，默认输入目录下的 `<输入文件名主干>_multicore_res.json` |
| `--version` | 输出程序版本 |

选项支持空格分隔和等号赋值，例如 `--cores=4 --output=out/plan.json`。程序不读取标准输入；错误信息写入标准错误。

输出 JSON 顶层包含两个字段：

- `node_to_subgraph`：非 COPY 操作 id 到非负整数子图编号的映射。
- `core_schedules`：长度为 N 的数组，各元素为对应核心的子图执行顺序，允许空核心。

每个计算操作对应一个子图，每个子图在核心队列中出现一次。同核子图合并为 Task 后复用核内数据，子图编号边界本身不引入搬运。

退出码：0 成功；1 内部错误；2 命令行错误；3 输入错误；4 输出失败；5 无法生成合法方案。

## 固定硬件参数

| 参数 | 数值 |
|---|---:|
| 每核 L1 容量 | 1,572,864 bytes |
| 每核 UB 容量 | 131,072 bytes |
| 共享 DDR 总带宽 | 60 bytes/cycle |
| 跨核等待 | 1,000 cycles |

这些参数定义在源码常量中，无需配置文件。

## 算法设计

### 1. 计算图建模

解析张量、操作和依赖边，收缩边界 COPY，建立计算操作 DAG、拓扑序与关键路径信息。通过写者组约束，将共同写入同一张量的操作作为整体处理，避免迁移时拆开共享写者。

### 2. 多初解构造

沿关键前驱将操作组织为不分叉的链，结合计算负载与通信代价切分链段，再将链段放置到核心。对不同核心预算生成候选，同时使用区域划分、依赖等待空隙和内存压力策略，兼顾并行计算与数据复用。

### 3. 分层候选评估

首先使用快速模型估计管道负载、跨核通信和内存压力，筛去较差候选；随后对少量候选进行共享 DDR、多管道及依赖等待的事件估价。张量搬运按跨核心的数据需求计算，容量压力结合张量存活区间估计。内部估价用于候选排序，方案的最终分数由官方评估器计算。

### 4. 多起点局部搜索

从多个完整初解出发，采用链段迁移、消费者组迁移、写者组交换、合法拓扑重排和内存窗口排序生成邻域候选。最多四条独立搜索路线分别维护候选池，结束后按统一比较键归并。

内部搜索预算设为 20 秒，计时从计算图构建完成后开始，覆盖初解构造与追加搜索；输入解析和结果写出独立执行。追加搜索在协作检查点响应截止，保留已完成的候选。时间预算会影响完成的候选集合，重复运行可能得到不同方案。

### 5. 方案输出

对选定方案检查操作覆盖、唯一调度及依赖顺序，再序列化为规定的 JSON 格式。结果先完整写入临时文件，写入成功后替换目标文件。

## 源码结构

| 文件 | 职责 |
|---|---|
| `src/main.cpp` | 命令行、输入输出、程序入口与退出码 |
| `src/model.hpp` | JSON 解析、图模型、固定参数、快速估价 |
| `src/chain.cpp` | 链分解、链段放置、多初解构造 |
| `src/regions.cpp`、`src/slack.cpp` | 区域划分与等待空隙候选 |
| `src/spill.cpp` | 内存压力导向的候选生成 |
| `src/refine.cpp` | 共享 DDR 与多管道事件估价 |
| `src/anytime.cpp` | 搜索预算、多路线搜索与结果归并 |
| `src/tensor_neighborhood.cpp` | 消费者组迁移与写者约束 |
| `src/memory_grid.hpp` | 内存排序参数的交错枚举 |
| `src/search_limits.hpp` | 搜索预算与候选数量配置 |

## 第三方库

无第三方库。JSON 解析与调度算法由工程源码实现，仅依赖 C++17 标准库；Windows 下的字符转换和文件替换使用系统接口，并通过平台宏隔离。
