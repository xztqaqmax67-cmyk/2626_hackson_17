# DAG Chain Solver v11（0.11.1，整體生成預算）

v11 在鏈／群組貪心分核後加入模擬退火（SA）。0.11.1 將整個生成程序改為共用時間預算，以在本機約 15～20 秒內完成較大用例為目標；搜尋在 18 秒停止開啟新工作，目標 20 秒包含收尾。較小用例做完就返回，不會 sleep 湊足 15 秒。原 v10 與上一輪 0.11.0 的部分結果保留；求解器不讀歷史答案，也不依公開測試點名稱選參數。

預算是合作式截止，**不是任意大小輸入都能硬性在 20 秒返回的保證**。輸入解析、首個可用方案、已開始的完整官方規則重播及輸出不能安全任意截斷，作業系統排程也會影響實際時間。所有階段從讀圖前的同一時鐘起點計算，不是每個階段重新取得 20 秒。

| 階段 | 從共同起點起的截止秒數 |
|---|---:|
| 初始候選搜尋 | 8.0 |
| 溢出回饋 | 10.0 |
| 搬運群組搜尋 | 11.5 |
| v10 候選及精算 | 14.5 |
| 貪心／SA 與候選精算 | 18.0 |
| 整體目標，含約 2 秒收尾餘量 | 20.0 |

階段提前完成時立即進入下一段，下一段可使用剩餘時間。截止時保留本次最後完整完成並接受的候選，放棄未完成估價。**不再保證完整跑完 v10.1，也不再承諾分數不低於未限時 v10.1。** 固定隨機種子仍保留，但不同系統負載可能使搜尋停在不同位置，因而輸出不同方案。

正式輸出格式仍只有 `node_to_subgraph` 與 `core_schedules`。鏈／群組僅要求同核，不要求連續執行；分核後仍在原始 DAG 上安排全部運算。

## 實際流程

1. **有截止的前段搜尋。** 先建立本次可用方案，再在各段期限內執行原有搜尋、溢出回饋、搬運分組與 v10 精算；最後取得本次入口，而非強制等待整套 v10.1 完成。
2. **獨立貪心分核。** 以搬運成本建立鏈與同核群組，使用兩種設定：`scale=0.5` 加 Tensor 聯集大小啟發式限制；`scale=1.0` 不以聯集大小限制群組。兩者皆保留工作量／節點上限及完整 writer 閉包。以 `pack_decomposition` 貪心分核，搬運權重分別為 2、4。
3. **貪心方案先精算。** 每個分核用 critical／DFS 兩種就緒優先序排程，共至多 4 個方案；時間允許才繼續生成與精算，截止可能截短此前綴。
4. **每個貪心分核至多退火兩次。** 共至多 4 個固定種子的 run，每次從該貪心分核重新開始，最多 1024 次提案，也受剩餘時間限制。move 移動完整群組；swap 交換兩個完整群組。較差中間狀態可以按溫度接受，已找到的最佳狀態另外保存。
5. **候選重新排程。** 每個 run 最多保留 4 個不同分核，優先保留低能量、貪心、低邊界搬運、低 Pipe 負載等狀態。每個候選再以原 DAG 的 critical／DFS 優先序排程，按最終各核操作序列去重。
6. **官方規則精算選優。** 從估時、估計總搬運、Pipe 負載三種排序交替取最多 4 個 SA 候選，與本次入口及貪心結果比較。先最小化精確 cycles，同 cycles 才最小化總 COPY bytes；非法候選不能勝出。最後只輸出精算勝者。

新增階段最多 `1 個入口重算 + 4 個貪心 + 4 個 SA = 9` 次完整多核方案精算；加上 v10.1 最多 14 次，最後兩階段合計最多 23 次。這不包含前段另外計數的 Step2 重播及近似細估，也不是每個核心各有這份配額。

SA 將當下剩餘時間的 55% 留給候選生成／排程，其餘留給完整精算。每次底層退火再預留 `min(0.25 秒, 當時候選預算剩餘時間的 20%)`，使停止退火後仍有機會排出最佳分核。這些是工作上限與時間分配，不保證每個 run 都跑滿。

最後的入口必須完成一次官方規則精算，才允許輸出；即使可選搜尋已截止，也會完成此合法性核對。若入口無效，程式回報錯誤而不寫出非法方案。最後選出的候選均經完整精算，未完成候選不能取代它。cycles 優先的比較只適用於本次實際完成評估的候選。

## SA 的估價與合法性

令 `L[c,p]` 為核心 c、Pipe p 的運算工作量，`W[p]` 為該 Pipe 的總工作量；每個原始運算以 `max(1, cycles)` 計入代理負載。`B` 是按 Tensor 來源／目的核心集合去重後的邊界搬運估值，另含直接 Op 邊的跨核 COPY、輸入讀取及最終輸出。能量為：

```text
E = max(max(L[c,p]), B / 60)
    + 0.03 * B / 60
    + 0.01 * sum(L[c,p]^2 / max(1, W[p]))
```

同一 Tensor 的多個消費者在同一核上只計同一份目的核資料需求；移走其中一個消費者時，其他消費者的搬運需求仍保留。此估價**不包含實際溢出、跨核同步等待及全域 Pipe／DDR 重疊**，只引導搜尋，不能直接作為最終評分。

完整步數的溫度由 `0.02 * max(1,E初始)` 幾何下降至 `0.0001 * max(1,E初始)`；提前截止可能尚未降至終點。若 `ΔE > 0`，接受機率為 `exp(-ΔE/T)`；較好或相同能量直接接受。種子由固定常數、核心數、群組變體與 restart 編號決定，不使用時間、檔名或測試點標識；時間截止本身仍會影響可完成的搜尋範圍。

同核群組與同 Tensor 全部 writer 先做傳遞閉包，退火途中不拆開。群組可能在 DAG 上不連續；程式不收縮群組成為必須整塊執行的超節點，不刪依賴，也不以收縮圖出現環為由拒絕原本合法的 DAG。Tensor 聯集大小不等於同時駐留量，實際容量與溢出由完整官方規則重播決定。

搬運與負載使用增量帳本；拒絕時反向恢復整數引用計數，並回填原浮點總量，避免撤銷累積誤差。每 64 個實際評估提案重建檢查，輸出候選再以完整帳本重算。更多上限與代價見 [SEARCH_LIMITS_zh.md](SEARCH_LIMITS_zh.md)。

## 建置與使用

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --parallel 4
build/bin/npu_sched input.json -n 5 -o output/plan.json
```

Windows 執行檔帶 `.exe`。`-n` 支援 2～5，表示 NPU 核心上限；`--version` 為 `dag-chain-solver 0.11.1`。正式 CLI 不新增搜尋調參旗標。整體預算位於 `src/search_limits.hpp` 的 `generation_*`，修改後重新編譯。將 `generation_budget_enabled=false` 並保持 `enable_timed_search=false`，才會回到固定工作量的完整流程；舊 `total_seconds=15` 只控制舊版前段追加搜尋，不能用來修改本版整體預算。

設定 `CHAIN_BUILD_TESTS=ON` 會另外生成實驗程式：

```sh
build/bin/npu_sched_experiment input.json -n 5 -o baseline.json --ablation baseline
build/bin/npu_sched_experiment input.json -n 5 -o greedy.json --ablation greedy_only
build/bin/npu_sched_experiment input.json -n 5 -o annealed.json --ablation annealed
```

三者分別停止在本次前段入口、再加貪心、再加退火；啟用預算時不代表完整重現未限時 v10.1。各次獨立執行的時間負載可能不同，不能假設其候選前綴完全相同。本輪使用 `scripts/run_v11_budget.py` 生成及外部官方評分、`scripts/summarize_v11_budget.py` 彙整，結果保存於 `reports/budget20/RESULTS_V11_BUDGET20.json` 與同名 `_zh.md`。生成時間不含外部官方評分。

stderr 的 `budget_stats` 記錄共同預算、各階段結束時間與截止情況；另有 `feedback_stats`、`communication_stats`、`v10_stats`、`annealing_stats`。每個 run 的種子、提案／接受／跳過／觸碰數及精算候選結果可供稽核。`candidate_seconds` 包含 `annealing_seconds`；`v10_stats.exact_seconds` 包含 `tail_seconds`，不可重複相加。限時模式可能省略勝者的近似診斷刷新，見 `diagnostics_current`／`diagnostics_refreshed`；精確 cycles／COPY 才是最終方案的評分依據。完整生成秒數以外部程序量測為準。

SA 迭代本體平均 **0.024 秒**，整個新增 v11 階段平均 **1.397 秒**；後者包含入口及候選精算，不能將兩者相加。最終 C++ cycles／總 COPY 與外部官方 **40／40 一致**，新增階段 360 次精算無 invalid。

## 檔案與備份

- `src/annealing.hpp/.cpp`：完整群組 move／swap、增量能量與退火。
- `src/annealing_search.hpp/.cpp`：貪心起點、原 DAG 排程、候選篩選與精算保底。
- `src/search_limits.hpp`：run／排程／精算數量；`src/annealing.hpp`：每個 run 的步數、溫度與觸碰上限。
- [CHANGES_v11_zh.md](CHANGES_v11_zh.md)：本版變更與驗證狀態。

每輪修改前執行 `python scripts/backup_changed.py descriptive_label src/file_a.cpp src/file_b.hpp`，只備份明確列出的改檔。`backups/` manifest 記錄舊雜湊，新檔記錄 `existed=false`；不要整份複製工作目錄。v11 初始來源與 v10.1 基準分別記錄於 `reports/initial_source_manifest.json` 與 `reports/v10_1_baseline_manifest.json`。

`scripts/package.py` 產生 `dist/dag_chain_solver_v11_1.zip`，只含源碼、CMake 與三份說明，預設 `CHAIN_BUILD_TESTS=OFF`；完整工作目錄另保留測試、官方材料與結果。舊版本資料不覆寫。
