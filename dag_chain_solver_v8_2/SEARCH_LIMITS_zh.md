# 0.8.1 搜索工作量说明

正式入口使用 `solve_fixed_work`。所有配额在 `src/search_limits.hpp` 中固定，运行时不接受时间、配置或随机种子参数。硬件常量是比赛规则，与搜索配额分离。

## 搜索顺序

先完成原有 v7 的链、区域、等待空隙和内存压力候选，保存每种核心预算的赢家，再进行固定次数的多起点追加搜索。各路线使用自己的候选池、去重表和游标，等待全部路线完成后按固定顺序归并，完成先后不影响输出。

`graph_work = 操作数 + 边数 + Tensor 数`。只依赖图结构，不能使用用例名称、文件大小或哈希选择策略。

| 配额 | 小图 | 中图 | 大图 |
|---|---:|---:|---:|
| graph_work | ≤80000 | ≤200000 | >200000 |
| 每路线追加轮数 | 4 | 2 | 0 |
| 独立路线数 | 最多4 | 最多4 | 0 |
| 每轮候选尝试 | 最多96 | 最多96 | 0 |
| 每轮全图粗估 | 最多12 | 最多12 | 0 |
| 每轮事件细化 | 最多3 | 最多3 | 0 |

小图合计最多192次追加粗估、48次追加细化，另有最多1536次候选构造尝试。重复、无变化或无效候选也可能消耗构造时间，因此不能只用精评次数估计总耗时。种子搜索的工作量另外计算。

原有种子配额保持不变：链参数组合10/6/2，粗候选池保留时间和搬运等不同取向，局部修改和区域候选都有固定上限。大图使用较少种子并跳过部分扩展。

## 候选内容

追加候选包括合法拓扑重排、内存权重和ready窗口、消费者组迁移、写者整体迁移、链段调整、负载补偿。有效内存参数网格会略过窗口1时只改变权重而不改变结果的重复组合；共享写入者必须保持同核，所有候选仍需验证。

每个候选先快速估价，再对少量入围者做共享DDR事件细化。最终比较以细化周期为主、搬运为次，再用完整方案作为平手键。内部模型不能替代官方评估。

## 确定性与时限

正式路径不根据墙钟停止或选优。计时只作研究统计；保留的 `solve_for_budget` API用于开发，不是正式默认路径。无效或未完成候选不能覆盖已完成的赢家。

固定工作量并不是对任意大小输入、任意硬件的90秒数学保证。验收必须实测；超大图按结构规模缩减工作量，为输入输出保留空间。不得把外部测试脚本90秒看门狗说成程序主动截止。

官方Step1/2精确移植模块仅留在研究测试中；正式主程序不调用，也不纳入最终提交包。`feedback_*` 旧研究配额不影响正式输出。
