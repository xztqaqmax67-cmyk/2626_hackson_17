# 17 队 DAG 多核调度器 0.8.2

本程序读取计算图，为全部非 COPY 操作分配子图和核心，输出场景 B 调度方案。语言为 C++17，使用标准库；无需配置文件、网络、外部进程或第三方运行库。

## 构建与运行

Linux（GCC 9.4 及以上，CMake 3.16 及以上）：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
./build/bin/npu_sched "/path with spaces/graph.json" -n 4 -o "/path with spaces/plan.json"
```

Windows（Visual Studio 2019/2022，CMake 3.20 及以上）：

```powershell
cmake -S . -B build -A x64
cmake --build build --config Release -j
.\build\bin\npu_sched.exe "C:\input with spaces\graph.json" -n 4 -o "C:\output with spaces\plan.json"
```

生成文件直接位于 `build/bin/`，多配置生成器不额外增加 `Release/` 目录。Windows Unicode 参数转换由 `_WIN32` 宏隔离。程序支持中文和空格路径，不依赖当前工作目录。

## 调用约定

```text
npu_sched <graph.json> [-n N] [-o plan.json]
npu_sched --version
```

`-n`/`--cores` 接受 2、3、4、5，默认 4；`-o`/`--output` 指定输出路径。长短选项均支持空格或等号传值。省略输出时，写入输入目录的 `<case>_multicore_res.json`；输出目录不存在会自动建立。不接受配置、时间、随机种子或评分参数。

退出码：0 成功；1 内部错误；2 参数错误；3 输入错误；4 输出失败；5 无可用合法候选。错误写 stderr，成功调用不输出评分。输出 JSON 顶层仅有 `node_to_subgraph` 和 `core_schedules`。

固定规则：L1 1572864 bytes，UB 131072 bytes，DDR 总带宽 60 bytes/cycle，跨核等待 1000 cycles。程序不允许通过任何外部设置覆盖这些数值。

## 算法过程

1. **建图与收缩。** 解析 Tensor/Op 关系，收缩输入输出 COPY，建立计算操作 DAG，计算关键路径、写者组和拓扑顺序。每个计算操作对应一个子图，因此子图依赖沿用原 DAG，输出顺序取自合法拓扑序。
2. **链分解。** 依据不受资源限制的完成时间，选择关键前驱构成不分叉的链。按负载与通信权重切分链段，将相关操作尽量放在同核，降低跨核搬运。
3. **多种初始方案。** 对可用核心数 2 到 N 分别搜索。使用区域切分、关键路径、消费者等待空隙和内存压力等通用图结构生成候选；共享 Tensor 的写入者保持同核。
4. **两级估价。** 自主实现的快速模型估计管道负载、通信和内存压力；少数候选进入共享 DDR 事件细化。估价用于候选比较，不作为官方成绩，也不输出到方案文件。
5. **固定次数追加搜索。** 复用不同核心预算下的赢家，最多四条独立路线尝试消费者组迁移、链段迁移、合法顺序重排及内存窗口。小图每条路线最多四轮，中图两轮，大图跳过；每轮最多十二次粗估和三次细化。所有策略只由输入图和核心数决定。
   内存重排参数使用交错顺序：在较短前缀内覆盖不同拓扑优先级、窗口和权重，避免有限轮数反复尝试同一类参数。完整 132 个参数组合及搜索配额保持不变。
6. **归并与输出。** 始终保留已完成的初始候选，工作结束后按固定下标与完整方案比较键归并。线程完成先后、机器运行速度不参与选择。通过结构检查后完整写出，再替换目标文件。

保留内部估价更优的方案不等于保证官方评估更优。每个版本需在未修改的官方评估器上独立核验；公开用例通过也不能证明所有隐藏输入。

## 源码导读

| 文件 | 作用 |
|---|---|
| `src/main.cpp` | 参数、输入输出、退出码 |
| `src/model.hpp` | JSON、计算图、固定参数、拓扑和快速估价 |
| `src/chain.cpp` | 链分解、初始候选和核心数组合 |
| `src/regions.cpp`、`src/slack.cpp` | 区域分配及等待空隙候选 |
| `src/spill.cpp` | 自主内存压力导向重排 |
| `src/anytime.cpp` | 固定次数多起点搜索；限时接口仅保留供研究 |
| `src/tensor_neighborhood.cpp` | 消费者组及写者闭包迁移 |
| `src/memory_grid.hpp` | 内存重排参数的确定性交错顺序 |
| `src/refine.cpp` | 自主共享 DDR 事件估价 |
| `src/search_limits.hpp` | 编译期搜索工作量配额 |

正式 `npu_sched` 不链接研究用 `official_spill`/`spill_feedback`。最终提交包不收录这些规则移植文件、开发测试、官方评估器或数据；研究目录中的历史报告不代表本版本的新成绩。

## 第三方库

**无第三方库。** JSON 解析与算法由项目自行实现，仅使用 C++17 标准库。没有 `find_package`、包管理器、联网下载或预编译第三方文件。

## 版本与验证

0.8.2 在 0.8.1 上只改变内存参数网格的枚举顺序，保持完整参数集合、固定工作量、候选估价和最后选优规则。网格集合等价、前缀覆盖、固定搜索确定性和 CLI 测试通过。40/40 公开组合、64/64 独立合成组合均通过未修改的官方评估器，全部重复输出一致。

本机 Windows/GCC 13.2 Release 实测：平均加速比 1.975512240 → 1.995020388（+0.9875%），12 组改善、24 组持平、4 组回退；总 COPY 增加 42,888,768 bytes。最长生成 25.331 秒，采样峰值 159.54 MiB、5 条进程线程。本轮未重新验证原生 Linux/MSVC。完整收益、回退及源码/程序哈希见 [0.8.2 验证报告](reports/RESULTS_V8_2_zh.md) 和 [原始汇总](reports/RESULTS_V8_2.json)。

0.8.1 基于 0.8.0，加入固定工作量的多起点搜索，分离官方规则研究移植，修复临时输出与内部错误分类。性能和验收结果以本版本生成的验证报告为准，旧报告仅供比较。
