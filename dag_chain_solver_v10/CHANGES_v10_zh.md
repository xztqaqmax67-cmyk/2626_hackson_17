# v10 修改記錄

日期：2026-10-31。v9 保留不動；每輪僅備份修改檔案，見 backups/*/manifest.json。

## 0.10.1：擴充精算池與固定起點調序

- 原 0.10.0 的最多 3 個精算候選及平手順序完整保留，再從既有候選池補至最多 6 個。原候選、入口及保底結果全部在本次重新算出，不讀取歷史方案。
- 使用擴充池最佳方案的精確時間線，按 Pipe 空檔及下游工作延遲提出最多 4 個調序候選；移動完整前驅閉包，保留分核及同核群組約束。
- 從同一個固定起點另提出最多 4 個溢出調序候選。兩種候選交替精算、去重、只做一輪；接受新方案後不追加下一輪搜尋。
- 預設最多 14 次完整多核方案精算（6＋4＋4，包含原 3 個）。最終比較順序是精確 cycles、總搬運；cycles 更低可接受較多搬運，同 cycles 時總搬運較少才勝出。三個精確階段都保留前階段的最佳合法結果，不以近似估價否決精算收益。
- Step2 實體版本選擇由每條使用邊掃描全部 S 次溢出改為二分查找 O(log S)。使用位置之前或當時最後一次重載的判定不變，也適用於後續寫入者；未修改官方溢出、容量或計時規則。
- 增加兩次連續溢出的讀者／後續寫入者回歸測試，與原線性版本規則逐邊對照；增加獨立執行各階段時的舊候選前綴、保底結果及 stage gate 測試。
- 新增 `exact_legacy`、`exact_pool` 開發比較模式；正式 CLI 與輸出 JSON 不變，正式預設 `exact` 包含尾段調序。`tail_seconds` 包含於 `exact_seconds`，不是額外可相加的時間；固定工作量沒有 15 秒硬截止。
- 整體配額位於 `src/search_limits.hpp`；時間線閉包與距離細項位於 `src/timing_feedback.hpp` 的 `TimingFeedbackLimits`，詳見 `SEARCH_LIMITS_zh.md`。

### 0.10.1 官方成效與完成驗證

兩個階段各 40 組、共 80／80 官方評分通過。相對 0.10.0，exact_pool 平均單核加速比 **1.946856× → 1.947173×（+0.0163%）**，cycles 5 改善／35 持平／0 退步；完整 exact 為 **1.949478×（+0.1347%）**，24 改善／16 持平／0 退步。

完整版本合計 cycles **141,647,028 → 141,484,015（-0.1151%）**，總 COPY **7,089,383,872 → 7,091,369,792 bytes（+0.0280%）**，溢出 COPY **4,189,118,016 → 4,191,103,936 bytes（+0.0474%）**。40 組的核心分配皆未變，改善來自順序調整；本次沒有同時降低合計搬運量。

尾段相對擴充池另減少 151,234 cycles，24 點改善、16 點相同。按實際精算候選的最終採用來源，時間線 10 點貢獻 54,144 cycles，溢出調序 14 點貢獻 97,090 cycles。這兩類按本次評測來源統計，相同方案可能被其他生成器提出後去重；擴充池與尾段改善點有重疊，不能相加成 29 點。

完整生成平均 **9.982 秒**，0.10.0 歷史平均 **9.411 秒**，本輪最快／最慢 **0.126／29.273 秒**；未觀察到完整版本生成時間縮短。精算階段平均 **1.484 秒**已包含尾段 **0.826 秒**。版本獨立量測且環境波動未排除，不能由此分離出二分版本查找的性能效益。

兩編譯器各 17／17 CTest、64 組合成圖官方測試與重複一致性、CLI／26 項契約檢查已通過。新增 **144／144 組 C++／官方差分一致、0 組失敗**，涵蓋正式方案 40、合成圖 64、邊界案例 16、雜湊碰撞 4、精度案例 20 組；其中 **16 組由官方與 C++ 一致拒絕**，不算成功生成的合法方案。有效方案的 cycles、搬運、完整時間線、Pipe 順序、記憶體峰值及重用依賴均一致，詳見 [0.10.1 完整驗證紀錄](reports/upgrade/VALIDATION_V10_1.json)。新測試由 `scripts/run_v10_upgrade.py` 執行，`scripts/summarize_v10_upgrade.py` 彙整；方案／官方結果保存在 `runs/upgrade/official_exact_pool`、`runs/upgrade/official_exact`，相容性抽查在 `runs/upgrade/official_exact_legacy`。新報告使用 `reports/upgrade/RESULTS_V10_1.json`、`RESULTS_V10_1_zh.md`、`RESULTS_V10_1_FINAL_zh.md`。

## 0.10.0 歷史修改

- 新增 Tensor 共用關係分組與熱點拆分候選，允許分叉同核群組，不強制連續執行。
- 加入有界、多樣化的候選及多起點溢出回饋，所有起點共用配額。
- 新增官方 Step3／Scene B 計時移植，只用於最後少量候選的精確比較；移植等價性以差分驗證為準。
- 最後精確選優以 cycles 優先，總搬運只作同分比較，保留合法的搬運／並行取捨。
- 開發執行檔提供累積階段比較，正式 CLI 與輸出 JSON 不變。
- 修正大於 2^53 的事件時間戳減法／比較及診斷精度；按本次官方 CPython 3.11.11 的整數 set 順序處理容量重用，補大 ID／雜湊碰撞測試。
- 搜尋狀態保留群組約束差異，最終計時則去重相同正式方案；多起點配額不重複放大。
- 最終40組官方評分：22改善／18持平／0退步；平均加速比 1.936588× → 1.946856×（+0.5302%）。平均生成 9.411 秒，其中最後完整精算平均 0.341 秒。
