# v0.2.1：單執行緒的新規則對照版

本版獨立放在 `dag_chain_solver_v2_rules`，原 `dag_chain_solver_v2` 與 `dag_chain_solver_v3` 不被替換。
目的為在相同規則與演算法下，比較 v2 的同步執行和 v3 的平行搜尋。

## 與原 v2 的差異

回移 v3 `0.3.1` 已實作的新規則：

- 區分 90% 溢出軟門檻與硬容量，並在每個操作配置全部輸入、輸出後統一檢查。
- 無新配置的操作也檢查軟門檻；先檢查瞬態容量，才釋放末次使用的資料。
- 部分寫入期間換出不再直接判不可行；保留原候選，額外嘗試集中寫者的排序。
- 延續 dirty backing 記帳；重新寫入後不能沿用舊 DDR 備份。
- 最遠下次使用相同時按駐留先後選擇換出項。
- 加入重複邊拒絕及最終方案的寫者同核驗證。

硬體常量仍是 L1=1572864、UB=131072、DDR=60、跨核等待=1000。
對齊的是問題 2／場景 B，沒有新增題目 1 或題目 3 的模型。

## 與 v3 的差異

為避免兩個分支的估價或搜尋細節不一致，本版從 v3 `0.3.1` 的必要來源建立，再將最外層搜尋恢復為同步迴圈。

| 部分 | v2 新規則版 | v3 0.3.1 |
| --- | --- | --- |
| `model.hpp`、`chain.hpp` | 位元組相同 | 位元組相同 |
| 候選生成、估價、修復、遷移 | 相同 | 相同 |
| 有效核心數 2..N 的工作 | 依序完成 | 平行完成 |
| 結果比較順序 | 固定，與 v3 相同 | 全部 join 後按固定次序 |
| 搜尋計算執行緒 | 主執行緒一條 | 含主執行緒最多四條 |
| 程式版本 | 0.2.1 | 0.3.1 |

`chain.cpp` 只移除平行執行 helper 的引用，將外層 `solve()` 換回原 v2 的 `active=2..N` 迴圈；
仍略過無可用候選的核心數，並維持由較大有效核心數開始的比較方式。
`main.cpp` 只有版本字串不同。CMake 移除不需要的 `-pthread` 與執行緒 helper 測試，
保留三項功能測試。提交 CLI 及 JSON 格式相同。

## 驗證結果

MSVC、MinGW 編譯與功能測試通過；兩輪共 800 次生成的 JSON 全部與 v3 相同。
40 組方案重跑官方評估全部通過，完整結果（排除方案檔名）與 v3 相同。
求解器速度比較與官方評分分階段執行，使用暖機、四對交錯量測與中位數。
一般排程觀察到波動後，再以相同高效能核心集合做受控補測；兩輪原始資料均保留。
受控輪整體生成速度提升 1.9794×，省時 49.48%；各核數與逐例結果見 `THREADING_COMPARISON.md`。
此比較保持候選與估價一致，沒有用舊 v2 的不同規則結果推論多執行緒效益。

目前估價沒有完整模擬 Step3 的容量重用依賴及跨核 FIFO 等待環；任何官方驗證結果都只適用於實際測過的輸入。
