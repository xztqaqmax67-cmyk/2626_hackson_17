# v6 0.6.2：吸收前辈 C++ 的改进与实测

日期：2026-10-30。源仓库：[2626_hackson_17](https://github.com/xztqaqmax67-cmyk/2626_hackson_17)。
下载基准提交：`0abae425a627bf2d051d42b98ff4d2e3a631bcd2`（v6 0.6.1）。本次版本为 v6 0.6.2，源码、测试与结果报告在本仓库同步保存。

## 结论

相同五核、15 秒预算的十个公开测试中，cycles **5 改善、3 持平、2 退步**。
总 cycles 从 **30,556,568** 降到 **30,308,663**，减少 **0.8113%**。
平均单核加速比从 **2.249665×** 到 **2.281835×**，提高 **1.4300%**。
总搬运量从 **1,647,460,416** 到 **1,662,917,952 bytes**，增加 **0.9383%**。因此这是执行周期的小幅改善，存在搬运量代价。

## 吸收了什么

1. 多路线搜索：沿用前辈 `problem2/search.cpp` 的代表种子和多路线思路，保留 v6 原初始搜索已算出的 2～5 核赢家。四路搜索从不同方案继续探索；同起点路线分摊枚举，独立起点遍历完整邻域。原初始总赢家一直保留。
2. 消费者组迁移与负载补偿：沿用前辈 `tensor_groups` 及消费者迁移交换的思路，只迁移某一来源核上的消费者 writer 闭包，生产者保留原分配。目标是已有该张量使用者的核；另尝试把五条流水线负载接近、与该张量无关的 writer 组交换回来。
3. 新候选分别尝试原顺序和合法 ready 重排，继续经过原粗筛、共享 DDR 细化及完整合法性检查。所有搜索共用原 15 秒预算，没有调用外部前辈程序、历史方案或逐用例答案。

前辈的 new90 类换页粗排、ready 窗口及阶段/链分解在 v6 中已有相似实现，本次不把它们当作新增贡献。没有移植前辈完整精评器。两项改动联合测试，未做单项收益消融，因此不能分别宣称各自贡献了多少。

## 方法与验证

- 两版均以 MinGW GCC 13.2、C++17、`-O2 -pthread`、静态链接构建；Windows Unicode 入口相同。
- 原版和改版分别串行生成所有十个方案，之后才统一官方评分；没有并发运行两个计时求解器。基线期间另有一次小型专项测试编译，额外复测用于检查关键变化的方向。
- 官方评估源码、输入和 config 按仓库固定 SHA256 清单校验；DDR 60 bytes/cycle、跨核等待 1000 cycles、L1 1572864 bytes、UB 131072 bytes 均未改动。
- 十个正式五核方案均通过官方 Scene B 评估。十组 C++ 测试、CLI 契约、26 个图输入契约，以及 16 张合成图 × 2～5 核共 64 次官方评估全部通过。
- 改版平均生成 14.92808 秒，范围 14.87544～14.96778 秒。
- 加速比 = 保存的官方单核 cycles / 当前方案 cycles；平均值是十个比值的算术平均。cycles 合计是不同测试点的总和，不是一张合并图的执行时间。
- 全十点首轮均保留真实输出，未按用例从原版与改版中挑较优结果。限时截断会受机器负载影响；保留初始赢家不保证胜过原版完整限时搜索，也不保证未知图、全部测试点或搬运量都更好。
