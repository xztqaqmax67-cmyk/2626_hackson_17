# v6.3 搬运取舍与快速筛查记录

日期：2026-10-30；基于 v6.2 提交 `4ddb75472d248d591fb29cd934e7843b00aa1cfe`。
本轮得到一个有周期收益的候选版本，以及可重复使用的短测流程；**尚未证明总搬运下降**。
正式求解预算仍为15秒。所有表格均为五核、官方评估的总 COPY bytes，负号表示下降。

## 保留的改动

原内存重排网格前32项全部是 window=1，改变内存权重不能改变唯一待选算子，
实际上至多只有4种顺序。现在先尝试 window=8/16/32/4、memory=1/2/4等有效组合，
最后保留4个 window=1模式，将160项缩成132项。新旧有效参数集合完全相同，
测试图前32项独立方案从4增至22。最终仍按估计 cycles 优先选优。

新版本不是“搬运越小越好”的策略：候选顺序调整可以找到更快但搬运略多的方案。
限时搜索会随机器负载、初始搜索耗时变化，不保证每个点都优于旧版。

同一个开发探针通过 policy=0/1 切换旧/新网格，其余正式求解路径相同。

## 短测与淘汰的方向

| 方向 | 初筛规模 | 官方结果 | 决定 |
|---|---|---|---|
| H1 有效内存重排优先 | 03/05/08/07，每侧3秒追加搜索 | 合计 cycles −2.0148%，COPY −0.0451% | 进入上述少量15秒验证；保留为v6.3候选 |
| H2 给低搬运候选第三个精评名额 | 03/05/08/09，每侧3秒 | 两侧方案和两指标全相同 | 停止加测，从正式路径删除 |
| H3 允许最多1%估计周期增加，要求至少1%估计总搬运下降 | 07/08/09，每侧3秒，H1对照H1+H3 | 三点均未触发取舍，结果相同 | 停止加测，从正式路径删除 |
| 单算子生命周期局部重排 | 五点共44个新候选 | 09最佳仅约0.023%改善，其余持平或退步 | 保留实验归档，不占正式搜索预算 |

H2保留粗筛前两名，以粗估周期不超过最快候选1.05倍为门槛，从余下候选按总搬运、
预测周期排序争取第三名；最终仍按周期优先。H3边界是内部模型边界，不是官方保证。
两者“本轮无收益”不等于证明方向永远无效。
生命周期筛查内部耗时合计4.68秒，但后续15次官方复评另用52.45秒，不能把全过程说成4.68秒。
源码及当时的H2/H3快照在 `experiments/traffic/`，均不参与默认构建。

## 测试效率与可靠性

直接把完整预算改为3秒不可行：大图原有初始搜索已经耗时约8～11秒，尚未进入追加搜索。
因此本轮采用固定同一个已完成的v6.2方案，重建并精评后，两种策略各追加搜索3秒。
准备时间单独记录（本轮约0.09～0.31秒），内部搜索约2.85秒；H3含读写的进程耗时约3.1秒。
**这不是从原始输入开始3秒即可得到最终方案的证据。**

- 后续新方向优先做2～4个代表点、每侧3秒；出现明显改善才做2～3点完整15秒。
- 边缘收益先复测一个点；明确无收益的方向立即停止，不默认十点全测。
- 生成阶段串行，结束后再官方评分，避免评分或并行编译抢占搜索预算。
- 方案始终做结构校验；完全相同的输入/方案/官方代码/config哈希可复用已有评分，并校验结果文件哈希。
- 记录内部估计与官方结果；只用官方结果报告真实 cycles/COPY，内部估计仅筛方向。
- 小测试验证候选集合、依赖与同核写者约束、超时返回完整赢家；不以短测替代规则检查。

H1/H2的早期 `wall_seconds` 包含Python结构校验和哈希开销，不适合作为精确进程耗时；
其中 `stats.total_seconds` 为程序内部总耗时。H3及最终复测已修正采样边界。
早期记录有程序哈希，但当时未保存每个程序的完整源码快照；不要将它们标为最终构建的逐字节复测。
H3保存当时源码/程序哈希；最终07复测附源码清单及程序哈希。其清单明确记录编译后仅补过API注释。

## 本轮回归与复现

MinGW GCC13.2：11组C++测试、CLI契约、26项图输入契约、16个合成图五核官方评估全部通过。
开发探针另通过20次零预算契约调用。未在Linux/MSVC重测本轮改动；CMake注册已检查，
本机使用直接编译，未执行CMake构建。生命周期归档的路径、语法及9项缓存入口检查通过。

从 `dag_chain_solver_v6` 目录：

```sh
cmake -S . -B build -DCHAIN_BUILD_TESTS=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --parallel 4
ctest --test-dir build -C Release --output-on-failure
python tests/search_probe_contracts.py --probe build/bin/search_probe --out runs/probe_contracts
python scripts/run_search_probe.py --probe build/bin/search_probe --out runs/screen_new --seconds 3 --mode resume --cases 03 05 08 07
python scripts/run_search_probe.py --probe build/bin/search_probe --out runs/full_new --seconds 15 --mode full --cases 07 08 09
```

Windows工具名加`.exe`。resume默认从 `runs/senior_15s` 读取冻结种子，可用 `--seed-root` 指定；
这个目录及完整评分证据随本轮交付包保存，Git仅保留摘要。官方材料可由原仓库固定归档提取。
`--cache-runs` 指定完整历史评分目录，`--build-manifest` 可保存并核验构建来源。
旧实验H2/H3的policy=2/5仅在快照工具可用，当前正式开发工具仅开放0/1。

下一步更值得尝试的是能同时改变跨核分配与张量存活峰值的块级调整，且按总搬运检查收益；
本轮单算子重排和单纯提高搬运偏好都没有足够证据值得继续扩大测试。
