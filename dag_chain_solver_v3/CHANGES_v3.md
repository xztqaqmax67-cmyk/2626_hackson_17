# v3：平行搜尋不同有效核心數

版本 `0.3.0`，建立日期 2026-10-30。此目錄從 `dag_chain_solver_v2` 複製必要原始碼後獨立修改；v2 保留。

## 改了什麼

v2 對要求的 N 核依序執行 `solve_at_core_count(g, 2)` 到 `solve_at_core_count(g, N)`。
v3 同時執行這些互相獨立的搜尋，等全部完成後，再以 v2 的固定順序比較候選。

| 要求的 NPU 核心數 | 獨立搜尋工作 | 求解器計算執行緒上限（含主執行緒） |
| --- | --- | --- |
| 2 | 有效 2 核 | 1 |
| 3 | 有效 2、3 核 | 2 |
| 4 | 有效 2、3、4 核 | 3 |
| 5 | 有效 2、3、4、5 核 | 4 |

每個工作仍包含單核候選。主執行緒執行有效 2 核的搜尋，其餘工作各使用一條新執行緒。
這裡的 CPU 執行緒數與輸出方案使用的 NPU 核心數不同；沒有新增命令列選項。

## 一致性與失敗處理

- 所有工作共用唯讀 `Graph`；候選池、去重集合、估價暫存及計數器由各工作獨立持有。
- 結果寫入預先分配的不同槽位，不在平行區共用 `push_back`、最佳解或輸出檔案。
- 所有工作完成並 `join` 後，按有效核心數遞增收集結果，再照 v2 從大到小比較。
  執行緒完成順序不參與平局處理，也不使用時鐘限制或亂數決定搜尋終點。
- 單項工作沒有可用候選時仍略過；其他工作例外在全部執行緒結束後，按有效核心數由小到大回報。
- 建立執行緒若發生 `std::system_error`，該工作改由主執行緒同步完成，不縮減候選集合。
  其他啟動例外也會先回收已建立的執行緒。
- 不建立巢狀執行緒；最多額外建立三條。`chain_baseline` 開發對照入口維持原本的單工作流程。

## 具體檔案

| 檔案 | 改動 |
| --- | --- |
| `src/parallel_jobs.hpp` | 新增有界執行、固定槽位例外收集、同步回退與 RAII join。 |
| `src/chain.cpp` | 只替換外層不同有效核心數的執行方式，合併與選解條件保留。 |
| `src/main.cpp` | 版本字串更新為 `0.3.0`。 |
| `CMakeLists.txt` | 更新專案版本，UNIX 編譯及連結加 `-pthread`，加入開發用平行測試。 |
| `tests/parallel_jobs_tests.cpp` | 覆蓋工作恰好執行一次、主執行緒參與、例外優先次序、join 及啟動失敗回退。 |
| `tests/check_outputs.py` | 重新生成 v2/v3 JSON、逐位元組比較與重複生成檢查；不呼叫評分器。 |

`reports/v2_source_manifest.json` 保存改版前 v2 檔案雜湊，供確認舊版未被改寫。

## 預期收益與限制

本版希望縮短「生成方案」的實際等待時間。搜尋集合與最終選擇規則沒有增加，
因此相同環境、相同輸入預期產生與 v2 相同的方案；多執行緒本身不會提高該方案的評分。
不同工作長度不一，較重的工作仍決定完成時間；2 核只有一個工作，不會得到這一層的平行收益。

同時存在多份搜尋暫存會提高記憶體需求，且執行緒啟動及競爭也有成本。
本版沒有實測加速比結論，不能把執行緒數當成速度倍數。更大輸入及正式環境仍需另行驗證時間與記憶體。

依使用者要求，**本版未執行評分**。功能檢查與輸出一致性結果記在 `NON_SCORING_CHECKS.md`；
官方合法性、Makespan、相對 baseline 加速比與總分，等待使用者提供官方評分器後再測。
